# Symbol -> (SymbolCategory, Iterator, PlanOperator) mappings for call-stack frame classification.
#
# Pipe-delimited: Module|Class|Function|Category|Iterator|PlanOperator. Lines starting with # and blank lines are ignored.
#   - Matching per field: "CQScan" = exact (case-insensitive), "CQScan*" = starts-with, "*Scan" = ends-with,
#     "*CQScan*" = contains, "*" = any.
#   - Category must be a SymbolCategory enum name. Iterator is the plan-operator badge text (blank = none).
#   - The most specific matching rule wins: an exact field beats any glob, a longer glob beats a shorter one, and
#     function is weighted highest and breaks ties. Only Module/Class/Function take part in this — Iterator and
#     PlanOperator are carried by whichever rule wins, they do not affect which one does.
#   - PlanOperator marks the frame where an operator starts executing, cutting the call tree into a segment per plan
#     node. It is matched (same glob syntax) against the showplan PhysicalOperator, so it must name a REAL plan node:
#     blank for anything the plan has no node for (Profiling, Row Iterator, SELECT).
#   - PlanOperator takes a COMMA-SEPARATED LIST, and matches if any entry does. One class routinely serves several plan
#     operators, and not always under related names: CQScanRange is the Index Seek, the Clustered Index Seek and the Key
#     Lookup (a lookup seek, which ExecutionPlanParser renames), so it needs "*Index S*,Key Lookup".
#   - The column is optional: a row that stops at Iterator just marks no boundary.
#   - A missing mapping costs more than the one operator: an operator with no entry frame contributes no boundary, so
#     its PARENT cannot trim that input away either, and the parent's segment swallows it.
Module|Class|Function|Category|Iterator|PlanOperator

# Statements. These ARE plan nodes: the parser synthesises one per statement (NodeId -1) whose PhysicalOperator is
# showplan's StatementType, so the names line up and the statement scopes like any other operator. Worth doing — it puts
# the connection/batch preamble above XretExecute outside every segment instead of inside all of them.

sqllang|CXStmtUpdate|XretExecute|StatementExecution|UPDATE|UPDATE
sqllang|CXStmtDelete|XretExecute|StatementExecution|DELETE|DELETE
